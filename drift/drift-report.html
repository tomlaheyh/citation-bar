The grid is the 31 days ending on the latest data day, the newest day in the data, which runs about two days behind today. Click a column heading to make it the focus. Its +0 is its baseline, read when the day was two days old. A day read for the first time at an older age has no baseline and shows N/A.

The +0 column holds the locked absolute value. Every column after it is that measure's cumulative change from the locked number, never a day-over-day step — so a single failed pull leaves one hole rather than corrupting everything after it. Colour carries direction only; the number carries the amount. Hover any cell for the absolute value behind the drift.

The pinned range columns are different. YTD is the whole year to the close date shown and All is the whole database to it. Each drift is one day's change — the same range measured on two consecutive mornings, so the window is identical and nothing of the change comes from the range getting longer. The columns to their right are cumulative from an anchor. Don't read across the divider as if it were one scale.

"(PubMed)" means PubMed's own Abstract filter (hasabstract). It counts a main abstract or an English plain-language summary, but not an abstract the publisher supplied separately, in any language. So no abstract (PubMed) includes records that do carry an abstract. The three ↳ rows under it split it, for all records and for MEDLINE. The English-other and no-abstract-at-all rows are read from each record's XML, so they exist for the daily cohorts only and are N/A for YTD and All. More in Help.

How PubMed changes during the day

These are the timings the collector is built around. They come from watching the data, not from an NLM schedule; NLM does not publish one.

  • Full-text links are added in a batch at 07:00 ET. It takes two passes to land about 97% of a day's links: about 85% on the first morning, about 12% on the second, under 1% on the third.
  • That is why the baseline is taken at age 2. A cohort read any younger has a full-text count that is not finished yet. Record counts settle much sooner.
  • The collector reads at 09:00 ET (13:00 UTC), after that morning's 07:00 batch. No other changes have been seen before 12:00 ET, so the run lands in a quiet window.
  • Winter shifts it to 08:00 ET. GitHub's schedule is in UTC and ignores daylight saving; 08:00 is still after the batch and inside the quiet window. GitHub can also start a scheduled run late, which the same margin absorbs.
  • The other collectors are staggered so no two commit at once. Both run monthly on the 5th: PubMed Summary at 14:00 UTC, Filters at 15:00 UTC.
  • A run started by hand at another hour reads PubMed at a different point in its day, so that day's numbers are not like-for-like with the rest. The report uses only runs from the current collector; earlier runs are left out.
